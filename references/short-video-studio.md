# 短视频工作室：单条 1 分钟内的脚本工位

短剧做多集叙事，短视频做单条抓停。两者共用同一套五工位骨架，差别在**预算**：短视频总时长是硬上限，口播字数、镜头数、钩子位置全都由它反推。

开工方式：

```bash
python scripts/studio.py init "短视频-项目名" --form short --target 60
```

工位名随形态变化：脚本台 → 素材台 → 分镜台 → 出片台 → **发布台**（短剧那边是后期台）。

## 一、时长预算：先算再写

60 秒不是「写到 60 秒」，是「只能装下这么多字」。

**中文口播语速 4.0-4.6 字/秒**。据此反推：

| 目标时长 | 口播字数 | hook 型镜头数 | 教程型镜头数 |
|---|---|---|---|
| 15s | 60-69 | 7-18 | 3-7 |
| 30s | 120-138 | 15-37 | 6-15 |
| 45s | 180-207 | 22-56 | 9-22 |
| 60s | 240-276 | 30-75 | 12-30 |
| 90s | 360-414 | 45-112 | 18-45 |

查预算不用记表：

```bash
python scripts/short_plan.py --target 60
```

> **不要抄英文旁白的数字。** 常见英文短视频教程给的是 1.5-2 字/秒，60 秒只有 90-130 字。那是英文单词节奏加广告留白，中文照抄会把 60 秒写成一半预算，成片全片空转。这条差异在 `docs/ecosystem-survey-2026-10-short-video.md` 有原始来源对照。

## 二、三档节奏：先选档再分镜

| 档位 | 单镜时长 | 每分钟镜头数 | 适用 |
|---|---|---|---|
| hook 型 | 0.8-2.0s | 30-60 | 抖音/TikTok/信息流/广告 |
| 教程型 | 2.0-5.0s | 15-30 | 科普/教程/产品演示/B站知识区 |
| 纪录型 | 3.0-8.0s | 8-15 | vlog/品牌片/慢叙事 |

**单镜不得短于 1.5 秒**。低于此值模型来不及完成切镜，两镜会糊成一团——这是硬下限，不是建议。

60 秒按 hook 型算是 30-75 镜，按教程型是 12-30 镜。选哪档由平台和内容决定，不由喜好决定：抖音不允许慢节奏，品牌片不该用 hook 型快剪。

## 三、禁止空帧

每个镜头必须有信息载荷。判定标准：

- 镜头 ≥4 秒，必须能说清这 4 秒在表达什么，否则砍掉
- 镜头 ≤1 秒，必须有强视觉刺激，否则浪费
- 用户说「这里安静一下」→ 追问「安静要承载什么？静默是一种信息，不是空白」

空帧是短视频最常见的浪费：60 秒里只要有 6 秒在等，完播率就掉一档。

## 四、钩子：前 3 秒定生死

**Hook 六分类**（拆解参考视频时按这个分类记录，才能横向对比）：

| 类型 | 做法 | 例 |
|---|---|---|
| curiosity gap 好奇缺口 | 抛一个不解答的问题 | 「他删掉了公司所有代码，然后……」 |
| shocking stat 震惊数据 | 具体数字造反差 | 「三年，四万张，全是糊的」 |
| bold claim 大胆断言 | 反常识的结论前置 | 「别学构图，先用坏一台相机」 |
| question 提问 | 直接问观众 | 「你的第一台相机还在吗？」 |
| visual hook 视觉钩子 | 画面本身抓停 | 手抖着拆开纸箱 |
| pattern interrupt 打断预期 | 反常规的动作或声音 | 镜头对准窗外，突然全部失焦 |

**钩子四不要**：不要第一镜放 logo 渐入、不要黑屏渐入文字超过 1 秒、不要主持人自我介绍、不要安静的标题卡。

**钩子必须单独写出来**，不能藏在口播第一句里——`short_plan.py` 会检查「钩子」小节是否存在，写成「随便/待定」直接判失败。

## 五、追问纪律：四种失效要防

AI 收集需求时有四种典型走样，写脚本前自查：

| 失效 | 表现 | 防御 |
|---|---|---|
| 凭印象瞎问 | 不查清单，想到什么问什么 | 问之前对照六维清单，确认每个维度为什么存在 |
| 和气接受敷衍 | 用户答「高大上/都行/随便」就放过 | 见模糊副词必须追问，逼成具体决策 |
| 自我满足提前结束 | 差不多了就开写 | 每维度对照接受标准，没齐不许进下一步 |
| 编造用户没说的内容 | 把空白填上「听起来合理」的东西 | 推断内容标 `[待确认]`，不许默默填入 |

**拒绝形容词**：「高大上、科技感、有质感」都不行，必须翻译成具体视觉决策。要问的是「第一个镜头里观众看到什么」，不是「你想要什么风格」。

六维必问清单：使用场景 / 目标受众 / 平台与时长 / 核心信息 / 现有素材 / 交付形态。用户一次答全就不必逐条问。

## 六、脚本文件结构

`脚本.md` 用固定小节，`short_plan.py` 按小节名取数：

```markdown
# 短视频脚本

## 钩子
（前 3 秒抓停的那句话，单独写）

## 口播
（逐字稿，字数按预算控制）

## 分镜
| 时间 | 画面 | 口播 | 字幕 |
|---|---|---|---|
| 0-3s | ... | ... | ... |

## 封面文案
## 话题标签
## 评论区引导
```

口播小节只写要说出口的字，不要混入画面描述——字数统计按这一节算，混入描述会让预算失真。

## 七、发布台：单条短视频的交付不止成片

短剧的后期台产出「成片」就算完；短视频的发布台要求**成片 + 发布包**双齐：

| 项 | 要求 |
|---|---|
| 封面文案 | 2-3 条候选，说清是什么 + 一个具体看点 |
| 发布文案 | 按平台给变体（抖音/小红书/B站 各一版） |
| 话题标签 | 3-8 个，混合大词与垂类词 |
| 评论区引导 | 一句能引发回答的问句 |

发布包放 `发布/` 目录，工位扫盘会把它计入完成判定：只有成片没有发布包，发布台不算完成。

## 八、机检

```bash
python scripts/short_plan.py --script 脚本.md          # 读 studio.json 里的 target_seconds
python scripts/short_plan.py --script 脚本.md --target 45
python scripts/studio.py check .                       # 串起分镜/引用/口播预算三道门禁
```

`short_plan.py` 检查六件事：口播字数是否落在目标时长的可听区间、单镜是否短于 1.5 秒、时间轴是否有断档、分镜总时长是否超目标、钩子小节是否存在且非敷衍、发布包三件是否齐。

退出码 0 = 预算内可交付，1 = 有硬伤。警告级问题（口播偏松、缺发布包提示）只提示不阻断。

## 九、与短剧形态的关系

| | 短剧形态 | 短视频形态 |
|---|---|---|
| 推进单位 | 每集一个目录 | 整个项目一条 |
| 脚本文件名 | `第X集/剧本.md` | `脚本.md` |
| 分镜载体 | 宫格 JSON | 脚本内的分镜表（也可放 `分镜/`） |
| 素材 | 角色 + 场景板，全剧共用 | 道具 + 场景，单条够用 |
| 末工位 | 后期台（拼接、配音、成片） | 发布台（成片 + 发布包） |
| 特有机检 | 引用核对、场景 state 同源 | 口播时长预算、钩子位置、发布包完整 |

两种形态共用 `studio.py status/check/board`，目录契约一致，所以同一个项目可以从短视频起手，后续扩成系列短剧。
