# 十段弹性路由（Stage Router）

> 用途：定义十个阶段、四种入口模式、阶段间的最小输入与唯一输出，以及回退时如何标记下游。
> 这是工位模型的上位协议：五工位不消失，降为十段里的第 05/06/08/09/10 段。

## 一、核心命题

顺序流水线解决「产物放哪、改稿往哪回流」，但假定用户每次都从剧本开始。真实场景里用户可能：

- 只有一句概念，需要从零起；
- 手上已有完整剧本，只需要分镜与提示词；
- 只改了第 8 场，想知道哪些下游要重做；
- 手上有关键的资产图，想直接出镜头。

弹性路由处理的正是这四种入口。它不改变生产方法，只决定**这一次从哪进、做完停在哪**。

## 二、十个阶段

| # | 阶段 | 最小输入 | 唯一输出 | 机检 |
|---|---|---|---|---|
| 01 | 概念锚定 | 一句话需求，或 `00_project/brief.md` | `01_story/synopsis.md` | 人工：三路径模板齐、一句话故事可复述 |
| 02 | 角色圣经 | 概念，或已有故事与角色方向 | `01_story/characters.md` | 人工：三维表齐、声音可辨测试 |
| 03 | 世界观（可选） | 复杂世界规则需求 | `01_story/worldbuilding.md` | 人工：系统能力/代价/知识层级表 |
| 04 | 分场大纲 | 概念+角色+目标时长 | `01_story/第N集/treatment.md` | 人工：逐场四问、六个审计标签 |
| 05 | 剧本融合 | 已有剧本资产，或已确认的 01-04 | `02_script/第N集/剧本.md` | `check_script.py` |
| 06 | 资产与场景板 | 最终剧本 | `03_assets/**`、`场景板/` | `check_refs.py`、`check_scene_plates.py` |
| 07 | 表演层（可选） | 当前场景/镜头 + 角色信息 | `04_performance/第N集/acting-vNN.md` | 人工：五支柱自检表 |
| 08 | 分镜与提示词 | 镜头目标 + 资产参考 + 表演 | `05_shots/第N集/sb.json`、`06_prompts/第N集/*.md` | `validate_storyboard.py`、`lint_prompt.py` |
| 09 | 出片与台账 | 分镜 JSON + 定稿帧 | `05_shots/第N集/视频段/*.mp4` | `manifest.py verify`、`task_ledger.py` |
| 10 | 后期与发布 | 视频段 | `05_shots/第N集/成片/*.mp4`、发布包 | `qa_batch.py`、`check_seams.py` |

**可选段**：03 世界观与 07 表演层。现实题材可跳过 03；表演层未写时，表演要求直接并入 08 的提示词（这是 v2 的既有做法，仍然合法）。可选段未写时 `studio.py status` 显示「可跳过」，不计入未完成。

## 三、四种入口模式

| 模式 | 用户话术示例 | 判定 | 行为 |
|---|---|---|---|
| 全流程 | 「从零开始：我要做一部 60 秒竖屏悬疑短片」 | 无既有资料，且目标覆盖多段 | 01 → 10 依次推进；**每段完成后停下等确认**，不自动往下 |
| 单阶段 | 「只做分镜」「只写这条视频的提示词」 | 点名了一个具体阶段 | 直接进该段，不补无关前序，不生成其他段产物 |
| 接力 | 「以我上传的最终剧本和角色卡为准」 | 手上有上游资料，明确指定权威输入 | 登记权威输入到 `project-status.md`，从资料能支持的那段进入 |
| 修订 | 「回到剧本段修第 8 场，先不要重做下游」 | 项目已有产物，要改上游 | 旧版移 `00_project/history/` → 切回目标段 → 标下游「可能过期」→ 不自动重写 |

**判定顺序**：先看是否点名了阶段（单阶段/修订优先），再看是否指定了权威输入（接力），都不是才按全流程。

## 四、阶段执行五步

每段都走同一套动作，不因段的不同而变：

1. **读控制文件**：`00_project/project-status.md` 与 `routing.md`，确认当前状态。
2. **确认本段**：本轮模式、目标阶段、权威输入、唯一输出。
3. **只读本段需要的资料**：不越界读其他阶段的产物；需要哪段就读哪段，读什么记录在 `routing.md` 的「本阶段允许读取」。
4. **产出唯一文件**，文件头写明状态、版本、实际输入来源。
5. **更新状态并停止**：改 `project-status.md`，等用户确认、修改、切换或结束。

**禁止**：一个阶段顺手把别的阶段也改了。想改别的段，等用户明确要求再切。

## 五、阶段间的最小输入与不补造原则

缺资料时**只列真正缺的最小项**，不要求补齐整条流水线。

| 用户想做 | 缺什么 | 怎么办 |
|---|---|---|
| 只做 08 提示词，但有镜头描述与参考图 | 不缺 | 直接做 |
| 只做 08 提示词，但没有角色卡 | 角色外观描述或参考图 | 问一次；用户说「你定」就写最小假设并标 `[假设]` |
| 只做 06 资产，但只有梗概 | 角色与场景清单 | 从梗概提取一份最小清单给用户确认，不写整本剧本 |
| 做 10 后期，但没有成片 | 视频段 | 报缺，不代做 09 |

**不补造**：缺上游时不生成整套上游来「凑」，只说明假设或问最小必要信息。为省事把 01-07 全套生成一遍，是最常见的越界。

## 六、回退与下游过期标记

上游改动后，**只标下游，不删不重写**。

1. 把要改的文件当前版本复制到 `00_project/history/<文件名>-v<旧版本>.md`。
2. 切换路由到目标阶段，只执行该段修订。
3. 在 `project-status.md` 的「可能过期的下游」里列出受影响的阶段与产物。
4. 修订确认后让用户选择：只保留新版、只重做受影响项、从某阶段整体重跑。

```
修订记录：从 06 切回 05；原因：第 8 场动机错误。
可能过期：第 8 场对应资产（06）、表演稿（07）、分镜（08）、视频段（09）、成片（10）。
未受影响：其他场次继续有效。
```

`studio.py status` 会自动比对文件时间给出同类提示；它是兜底，不替代显式记录。

## 七、阶段与旧五工位、旧三路线的映射

| 旧称谓 | 现在的位置 |
|---|---|
| 剧本台 | 05 剧本融合 |
| 角色与场景台 | 06 资产与场景板 |
| 分镜台 | 08 分镜与提示词 |
| 出片台 | 09 出片与台账 |
| 后期台 | 10 后期与发布 |
| 路线 A（分镜智能体） | 08 的技法一 |
| 路线 B（宫格直生） | 08 的技法二 |
| 路线 C（人脸审核规避） | 06 的审核规避技法 |

旧话术继续可用：「帮我把这个剧本做成漫剧分镜」= 进 06 → 08；「改了剧本哪些镜头要重出」= 修订模式 + `impact_graph.py`。

## 八、控制文件职责

三份文件各管一件事，不混写：

| 文件 | 管什么 | 谁写 |
|---|---|---|
| `brief.md` | 项目常量：受众、平台、时长、类型、视觉方向、预算、禁项 | 用户首次填写，之后少改 |
| `project-status.md` | 变量：当前模式、目标阶段、权威输入、已确认文件、可能过期下游 | 每次阶段推进后更新 |
| `routing.md` | 本轮路由：当前阶段、唯一输出、允许读取、方法来源、建议下一步 | 每次切段前更新 |

**不要**把故事内容写进这三份文件——它们是控制面，创作产物在 01-06 各目录里。

## 九、check 与 status 的口径

- `studio.py status`：扫盘得出十段进度，标出「当前焦点段」，附改稿回流提示。只读，不改任何文件。
- `studio.py check`：把机检串成一条命令；有失败项即 exit 1。
- 门禁不过不进下游：分镜 JSON 不合格直接出视频，返工成本远高于在分镜阶段改。

## 十、纪律

1. **一次只执行一个阶段**。不同阶段的方法互相串味是这条纪律要防的事。
2. **未确认不改其他阶段**。用户确认过的东西，不因为「顺便发现更好」就改掉。
3. **用户已有足够资料可直接进下游**，不得以「前序没跑完」为由强迫重做。
4. **附件与图片**，只有用户明确说「以这些为准」才成为本轮权威输入。
5. **不把其他项目的内容带进来**。
6. **每段产物同时给聊天展示与文件落盘**，只给路径不算交付。
