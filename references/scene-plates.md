# 场景板（Scene Plate）与场景资产

> 适用：需要跨镜头复用同一场景、或同一场景换时段／天气／观察方向的视频项目。
> 定位：场景图是画面的地理与光线基准，不是「一张底图」。把场景写成可复现的条目，才能解决四件事——重出一致、换代可追溯、描述单一来源、验收有依据。
> 关联：三层工艺分离见 `references/asset-workflow.md` 与 `references/frame-industrial.md`；@引用铁律见 `SKILL.md`；连续性与同源核对见 `references/continuity-log.md`。

## 1 四层资产与引用链

```
场景圣经（全片一份）
  └─ S-01 场景板（Location + state）
       ├─ S-01-V1 / V2（View，可选）
       ├─ 锁定句（一句，供分镜原样引用）
       └─ 场景图产出
            └─ 镜头首帧（可选）
                 └─ 视频提示词
```

两份交付各管一件事：

| 交付物 | 内容 | 定稿时机 |
|---|---|---|
| 场景与资产提示词 | 场景圣经、S-* 条目、参考声明、可复制正文、验收清单 | 先于分镜定稿（场景图产出前） |
| 分镜提示词脚本 | 只引用 `S-01` 与锁定句、素材绑定、逐镜视频提示词 | 场景图确认后 |

单场景项目可以只写一条 S-*，仍建议独立成文，作为下个批次的模板起点；多场景项目按 Location 建条目，避免场景描述散落在每镜提示词里。

## 2 ID、state 与 View

- `S-01`：Location 编号，全片唯一，不复用。
- state 后缀：`S-01@day-crowd`（白天、人群坐满）、`S-01@night-empty`（夜晚、空场）。**换代不是换文件，是换 state。**
- View：`S-01-V1`、`S-01-V2`，同一地点不同观察方向；View 不改变地理，只改变看它的方向。
- 分镜引用写法：`@图3＝S-01@day-crowd`。禁止只写「场景图.jpg」这种无版本文件名。
- 同一批镜头必须使用同一 state；混用两版场景即混源，接缝会跳，验收应拦截。

## 3 条目结构

每条场景板包含：编号、state、名称、用途、参考声明、空场政策、文字政策、画幅、锁定句、可复制正文、反推核对（补存量条目）。

可复制正文分六段：

1. 头部：画面类型、画幅、整体调性（一句）。
2. 【地理】：从哪里看、看哪里、什么在哪一侧、怎么进出。
3. 【固定锚点】：1–4 个强锚点，写清相对位置不得移动。
4. 【光线】：主光来源、方向、色温、暗部与次要光。
5. 【材质与色彩】：材质、主色，声明无滤镜、无 LUT、无色调映射。
6. 【排除】：不出现什么（不含运镜与人物动作）。

## 4 写法规则

1. **地理优先**：先写「从哪里看、看哪里、什么在哪一侧、怎么进出」，再写材质装饰。只留 1–4 个强锚点，其余概括。禁止写成物件清单。
2. **一个 View 一个方向**：同一句里不能把同一扇门同时放在左右两侧；换方向就新建 View。
3. **光线必须可解释**：写主光来源、方向、色温、暗部；不写「电影感光线」这类空词。同一 Location 同一 state 的多个 View，主光来源、色温关系、光比方向必须一致；有差异写 delta 并说明成因。
4. **空场政策三档**：`required`（绝对无人）、`preferred`（以空场为主，允许无身份尺度参照）、`not_required`（可有人群）。正文与政策冲突即阻断。
5. **文字政策双层**：来源政策（`exact_readable / graphic_only / no_readable_text / pending_creator_text`）加本次呈现方法（`readable / symbolic / blank / postproduction`）。短剧与视频项目默认 `postproduction`，画面文字一律后期叠加。
6. **参考图声明**：用途只取地理、构图、尺度、风格、造型状态之一，一张图不承担两件事；写清「控制什么」和「不得控制什么」，禁用「全参考」。
7. **不写运镜、不写人物动作**：这两项属于镜头层。场景板写运镜会被视频模型当成画面内容，也会与分镜的运镜句冲突。
8. **保真红线不外溢**：场景板默认不含服装与面料。需要人物出镜的氛围图另立条目，并声明服装／面料以该款基准图为唯一依据，不与场景底图混用。
9. **场景基准描述复用**：同一核心场景只写一份基准描述，后续构图变化只改机位、景别与前后景，不重写地理与光线。改一处即全片生效。
10. **锁定句唯一来源**：锁定句只在场景单定义，分镜脚本原样复制，不得改写。调整措辞先改场景单并升版，再同步分镜。

## 5 反推补存量

已有场景图但没有提示词时：

1. 把场景图、条目模板与反推指令交给多模态模型。
2. 输出必须独立可用：不出现「参考图 / 原图 / 对标 / 复刻 / 替换」；地理、锚点、光线、文字状态逐项写清；不新增原图没有的元素；每张只加一个轻升级点。
3. 人工核对四项：锚点相对位置、主光方向、文字状态、画幅。任一项不符只重写对应段落，不整条重来。
4. 落成 S-* 条目，场景图文件名带 state；旧版移入 `_旧版归档/`。

完整反推指令与数据模板见本技能 `scripts/gen_scene_sheet.py` 的样例数据与项目承载文档；核对项固定为上述四项。

## 6 场景图验收

逐项核对，全部通过才可作为全片基准：

1. 入口、尽端、左右关系与场景板一致。
2. 固定锚点数量与相对位置一致，没有被装饰淹没。
3. 主光方向与色温与全片口径一致，暗部没有压死。
4. 空场政策被执行（舞台／主体区无人，人群状态符合政策）。
5. 无参考图以外的文字、水印、平台标识。
6. 画幅、分辨率、色彩模式符合批次口径。
7. 与上一版对比时，差异只出现在 delta 列出的项。
8. 与分镜脚本的锁定句逐字对得上，state 与脚本固定素材组的标注一致。

不合格时只改对应段落：地理或锚点错重写地理段与锚点段；光线错只改光线段；文字错先改文字政策，仍出现则后期处理，不用更强的负面词硬压。视觉一致性必须人看，机检不代判。

## 7 与分镜脚本对接

- 分镜脚本的固定素材组：写场景文件名与当前 state，不写场景外观。
- 场景章节：只写场景编号、文件名与锁定句，删除重复的场景特征长段。
- 每镜的素材绑定句统一引用锁定句（原样复制），不再各自改写；这样一条改动全片生效。
- 换 state 的顺序：先验收新 state 的场景图，再改场景条目与锁定句，然后升版本文件，最后同步分镜的素材组与场景章节，并整批换图，不逐镜混用。

## 8 工具

| 工具 | 用途 | 常用命令 |
|---|---|---|
| `scripts/gen_scene_sheet.py` | 读数据渲染场景单 md，可直接生成 docx | `python scripts/gen_scene_sheet.py <数据.json> --verify` |
| `scripts/check_scene_plates.py` | 场景板机检：字段、ID/state、政策冲突、光线、字数、敏感词、跨文件引用 | `python scripts/check_scene_plates.py <数据.json> --script "<分镜脚本.md>"` |
| `scripts/manifest.py` | 生成清单记录每段视频的脚本版本与场景 state | `python scripts/manifest.py init "<分镜目录>" --scene-state S-01@day-crowd` |
| `scripts/qa_batch.py` | 一键验收底账，含场景 state 一致性 | `python scripts/qa_batch.py "<分镜目录>"` |

数据文件是唯一来源，场景单正文不手改。docx 生成链复用 article-format 的 md2docx 与 article_style，输出直接落交付路径；新版产出后按旧版归档规则处理旧版。

## 9 常见错误

| 症状 | 根因 | 处置 |
|---|---|---|
| 改了场景但某镜没变 | 场景描述散落在脚本与口头沟通两处 | 锁定句只留场景单一处，脚本原样引用 |
| 接缝突然跳色／跳光 | 同批镜头混用两版场景图，文件名相同 | 换代建 state，整批换图；manifest 记录 scene_state 并机检 |
| 生成图里出现运镜或人物动作 | 场景板写了镜头层内容 | 场景板只写地理、锚点、光线、材质、排除 |
| 场景图带人物导致服装被改 | 场景板与服装资产混用 | 场景板默认空场；带人另立条目并声明面料基准图 |
| 参考图「全参考」后服装被换 | 一张图承担了多件事 | 参考声明拆用途，写清不得控制项 |
| 画面文字乱码或多余标识 | 文字政策与正文要求冲突 | 先定来源与呈现政策，再写正文；文字一律后期 |
| 多场景拼在一张图 | 没有单一核心场景约束 | 拆成不同 S-* 条目或不同 View，一条一张图 |
