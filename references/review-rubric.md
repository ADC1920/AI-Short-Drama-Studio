# 审查规则表（Review Rubric）

> 用途：把「视觉验收真看」「只声称读过实际读到的部分」这类纪律落成可勾选的规则表。
> 分五个范围、共 27 条。每条给出编号、判据、不通过的具体样子、判定方式。
> 判定方式二选一：**脚本**（指到已有脚本，跑绿即通过）或**人工**（必须有人在审查记录里写出证据行）。
> 使用方式见第六节；审查记录格式由 `scripts/review_check.py` 机检。

## 一、审查结论四档

审查记录末尾必须给一个总结论，四档之一：

| 结论 | 含义 | 使用条件 |
|---|---|---|
| `APPROVE` | 通过 | 全部规则通过，无遗留问题 |
| `APPROVE_WITH_NOTES` | 通过但有备注 | 全部规则通过，但有值得记录但不阻断的观察 |
| `REVISE` | 退回修改 | 至少一条规则不通过 |
| `PROVISIONAL` | 证据不足 | 有规则无法判定（未亲看、缺素材、缺原片），**必须写明缺什么证据** |

纪律：`PROVISIONAL` 不等于通过。没看过就是没看过，不能拿「文件能打开」「脚本 exit 0」替代。

## 七、审查记录的格式

审查记录写在 `<项目>/_reviews/<范围或集号>.md`，格式固定，由 `scripts/review_check.py` 机检：

```markdown
# 审查记录 · 第1集

- 审查人：<填实际审查的人或 agent 标识>
- 审查时间：2026-11-12 20:00:00
- 范围：RA-S / RA-A / RA-B / RA-P / RA-F（列出本次覆盖的范围）

## 结论

APPROVE_WITH_NOTES

## 逐条

| 编号 | 结论 | 证据 |
|---|---|---|
| RA-S-01 | 通过 | check_script.py exit 0 |
| RA-S-04 | 通过 | check_script.py S5/S6 无错，钩子行 18 字 |
| RA-B-05 | 证据不足 | 未查看 组03 定稿图，缺该镜首帧 |

## 备注

（可选）值得记录但不阻断的观察。
```

机检规则（`review_check.py`）：

1. 有总结论，且在四档之内。
2. 总结论为 `REVISE` 时，逐条里至少有一条不通过。
3. 总结论为 `PROVISIONAL` 时，逐条里至少有一条证据不足，且该行证据列写了缺什么（不少于 6 字）。
4. 结论为 `APPROVE` 时，不允许存在不通过或证据不足的条目。
5. 每条有证据列且不为空。
6. 审查人、审查时间、范围三项齐。

## 八、与脚本的分工

规则表管「该查什么」，脚本管「结构性事实」，人工管「看过没有、判断对不对」。三者不互相替代：

- 脚本跑绿只证明结构合规，不证明内容好。
- 人工判定必须写证据行，写「已检查」不算证据。
- 无法判定时用 `PROVISIONAL` 并写明缺什么，不用「通过」蒙过去。

一个真实的边界：`RA-F-04`（视觉验收）永远只能是人工判定。任何脚本都无法替代「看一眼这个镜头里的人是不是同一个人」。
