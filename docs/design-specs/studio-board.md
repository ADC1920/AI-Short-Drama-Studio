# 设计规格 · 工作室看板（studio board）

> 触发来源：v2.0.0 工作室化重构。产物=`scripts/studio.py board` 生成的自包含 HTML 看板。
> 本条只覆盖看板的信息结构与视觉规范，不改技能其它文档口径。

## 一、调研结论（成熟形态参照）

| 参照 | 采纳的结构 | 不采纳的原因 |
|---|---|---|
| 即梦短剧工作室（2026-10-26） | 全流程同一处、角色与场景集中管理、局改同步关联环节 | 不复制其视觉与页面结构，也不依赖其 API |
| Linear 项目视图 | 左列分组导航 + 主区状态列表；状态用色点而非彩色整块 | 其交互（拖拽、筛选器）超出静态看板需要 |
| Notion 数据库视图 | 一行一条记录、字段对齐、空态有明确指引 | 不做内联编辑（看板只读，写操作走脚本） |
| Vercel 部署看板 | 阶段用横向进度条，失败项用红色左边框 | 不做实时轮询（单次生成，刷新即重算） |

**核心取舍**：看板是**只读视图**，所有写操作留在 CLI。理由：技能本体是 Markdown + 标准库脚本，看板若可变写会让「工位进度只认产物」这条纪律失效——状态必须由扫盘得出，不能由界面填写。

## 二、信息结构（三段）

1. **项目头**：标题、画幅、模型版本、集数、生成时间。
2. **五工位轨道**：横向五格，每格显示序号、工位名、进度 `done/total`、状态色、一行说明。当前工位（第一个非 done）高亮，其后的工位降透明度。
3. **下方两栏**：左=分集明细表（集号 / 剧本 / 分镜 JSON / 关键帧 / 视频段 / 成片）；右=改稿提示与下一步命令。

## 三、视觉规范

- 深色底（`#0f1115`）配中性灰层次，避免纯黑纯白；工具类界面按行业惯例用深色，减少长时间盯盘的视觉疲劳。
- 状态色只用三点：完成 `#3fb950`（绿）、进行中 `#d29922`（琥珀）、待开始 `#6e7681`（灰）。不用蓝紫渐变——那是最典型的「AI 味」配色，且与状态语义无关。
- 字体：系统无衬线栈（`-apple-system, "Segoe UI", "Microsoft YaHei"`），等宽仅用于数字与命令。
- 间距用 4 的倍数（4/8/12/16/24/32）；圆角统一 8px；边框 1px 半透明白。
- 信息密度优先：单屏可见五工位 + 分集表，不折叠、不弹窗。
- 无障碍：状态不只靠颜色，每格都有文字状态；正文对比度按 WCAG AA。

## 四、实现约束

- 单文件 HTML，内联 CSS，零外部请求（离线可看、可直接发给用户）。
- 数据全部来自 `studio.py` 的 `collect()`，看板不自己读盘、不自己判断状态。
- 不写 JS：静态快照，刷新页面即重算（重新生成文件）。
