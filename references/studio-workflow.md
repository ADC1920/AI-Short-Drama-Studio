# 短剧工作室：五工位流水线

把制作流程从「三路线并列选一条」改成「五个工位顺序推进、每工位有产物和门禁、改稿按层回流」。
路线 A/B/C 不再是并列的总路线，而是**分镜台内的三种技法**；其余工位对所有技法通用。

## 一、为什么改

三路线模型解决的是「手头材料不同，从哪进入」；真实制作里反复卡住的却是另外三件事：

- 一份资产（角色、场景、台词）在多个环节各存一份，改了一处别处不知道。
- 分镜改了，已经出的视频段没人提醒要重出。
- 剧本、分镜、成片混在一个目录里，进度只能靠人记。

工作室模型把这三件事变成结构：**一个项目目录承载全部产物，工位按目录扫盘判进度，改稿影响用文件时间自动提示。**
对标的产品形态是即梦 AI 短剧工作室（2026-10-26 上线，整合剧本整理、角色与场景管理、分镜生成、视频制作、后期调整到同一平台，配套 DreamScript / Anycook / DreamShot 三模型）。本项目是技能层的同构实现，不依赖该平台页面。

## 二、五个工位

| # | 工位 | 对标能力 | 本技能产物 | 门禁 |
|---|---|---|---|---|
| 1 | 剧本台 | 剧本生成与结构诊断 | `第X集/剧本.md` | 不是模板占位；有钩子与收尾；@引用名已注册 |
| 2 | 角色与场景台 | 角色与场景资产管理 | `素材/*.png`、`场景板/` | `check_refs.py` 无断链；角色走锚点法；场景有板与 state |
| 3 | 分镜台 | 分镜生成、对话改稿、导演台预演 | `第X集/分镜/` 下分镜 JSON + 定稿图 | `validate_storyboard.py` PASS；关键帧定稿；`lint_prompt.py` 无空词 |
| 4 | 出片台 | 视频生成与定点重拍 | `第X集/分镜/视频段/*.mp4` | `manifest.py verify` 同源；重生率 ≤10% |
| 5 | 后期台 | 人声分离、重新配音、成片 | `第X集/成片/*.mp4` | `qa_batch.py` 接缝量化；视觉验收真看；封面与文案齐 |

工位进度只认产物，不认口头状态：`studio.py status` 扫目录得出，人不填进度字段。

```bash
python scripts/studio.py init <项目目录> --title "剧名" --episodes 3
python scripts/studio.py status <项目目录>          # 五工位进度 + 当前焦点工位 + 改稿提示
python scripts/studio.py status <项目目录> --json   # 机读
python scripts/studio.py check  <项目目录>          # 串起分镜/引用/清单/场景板机检
python scripts/studio.py board  <项目目录>          # 出单文件 HTML 看板（默认 .studio/board.html）
```

看板是只读视图：所有状态由扫盘算出，界面上不能改，写操作一律回 CLI。这样「工位进度只认产物」这条纪律才不会被绕开。视觉规范留档在 `docs/design-specs/studio-board.md`。

## 三、数据契约

```
<项目>/
├── studio.json          项目配置：标题、画幅、模型、集数、场景板路径
├── 素材/                角色与道具参考图；文件名 = @引用名（全剧一套）
├── 场景板/              场景单数据（可选，有则纳入机检）
├── 第1集/
│   ├── 剧本.md
│   ├── 分镜/
│   │   ├── sb.json              宫格分镜 JSON（或 A 路线分镜表 md）
│   │   ├── grid01.png           定稿关键帧 = 该镜首帧
│   │   ├── _manifest.json       每段视频的提示词版本与场景 state
│   │   └── 视频段/段01.mp4 …
│   └── 成片/第1集.mp4
└── 第2集/ …
```

`studio.json` 只存手填项（标题、画幅、模型、集数、场景板路径），进度一律扫盘。
目录结构与 `scripts/init_project.py` 兼容——老项目直接补一个 `studio.json` 即可纳入工作室视图，不必搬迁。

## 四、改稿回流规则

改稿的代价随工位递增：剧本改动最便宜，成片重出最贵。所以改一层，必须回流到它下游的所有工位，禁止只改一处就交付。

| 改动发生在 | 必须回流 | 可保留 |
|---|---|---|
| 剧本台（台词、剧情） | 分镜台重写受影响镜头 → 出片台重出那些镜头 → 后期台重剪 | 未受影响的镜头及素材 |
| 角色与场景台（外形、服装、场景 state） | 分镜台重出受影响关键帧 → 出片台重出用到它的镜头 → 后期台重剪 | 剧本、其它角色 |
| 分镜台（提示词、构图、镜序） | 出片台重出该镜 → 后期台重剪 | 素材 |
| 出片台（单段重拍） | 后期台重剪该段 | 其余段 |
| 后期台 | 无 | 全部上游 |

`studio.py status` 会自动比对文件时间，给出两类提示：资产改动晚于成片、分镜改动晚于视频段。看到提示就按上表回流，不要跳过回流直接交付。

## 五、三路线在工位里的落位

| 原路线 | 现位置 |
|---|---|
| 路线 A 分镜智能体 | 分镜台技法一：有完整剧本，产出工程级分镜表（镜号/时长/转场/声音设计） |
| 路线 B 宫格分镜直生 | 分镜台技法二：只有梗概，产出宫格 JSON 与宫格图，一张图直生 |
| 路线 C 人脸审核规避 | 角色与场景台技法：资产被拦时的五种规避法，在进入分镜台之前解决 |
| 多集工作流 | 项目层：`第X集/` 分集与全剧共用素材，贯穿五个工位 |

三条路线之间不再是「选一条走到底」，而是分镜台按材料选技法、角色台按审核情况加技法。

## 六、另一种形态：短视频

本技能有两种形态，共用同一套五工位骨架与目录契约：

|  | 短剧形态（默认） | 短视频形态 |
|---|---|---|
| 建项目 | `studio.py init <目录>` | `studio.py init <目录> --form short --target 60` |
| 推进单位 | 每集一个目录 | 整个项目一条 |
| 脚本 | `第X集/剧本.md` | `脚本.md` |
| 末工位 | 后期台（拼接、配音、成片） | 发布台（成片 + 发布包） |
| 特有机检 | 引用核对、场景 state 同源 | 口播时长预算、钩子位置、发布包完整 |

短视频形态的完整工艺（时长预算反推、三档节奏、Hook 六分类、追问失效防御、发布包四件）见 `references/short-video-studio.md`。

判形态的口径：**一次交付一条、总时长 ≤60 秒、以抓停和发布为导向** → 短片形态；**多集、有角色延续、有集间衔接** → 短剧形态。两者目录兼容，短片起手后续扩成系列短剧不用搬家。

## 七、通用机制（两种形态共用）

以下四条来自同业实践，写进任何工位都要遵守：

**单镜时长下限 1.5 秒。** 低于此值模型来不及完成切镜，两镜会糊成一团。现有「单序列 ≤6 镜」是上限，这条是下限，两头都要卡。

**否定约束配正向清单。** 只写「不要 X」，模型要么把 X 相关的一切都掐死（画面死板），要么照旧乱加（禁令失效）。正确做法是双清单：禁止项 + 允许项，允许项每项带理由、质感参照、动态约束。例：

> 禁止：不出现霓虹光效、不出现镜头光斑
> 允许：允许暖色台灯的柔光溢出（参照钨丝灯的暖黄，范围限于灯罩周围 30cm）

这与「否定失效三改法」（换词根/主体优先句式/移除触发器）互补：三改法管「怎么把否定写对」，双清单管「否定之外还有什么可以做」。

**需求收集防四种走样。** AI 收集需求时容易：凭印象瞎问、和气接受敷衍、自我满足提前结束、编造用户没说的内容。防御办法是每次收集前对照六维清单，用户答「随便」必须追问，推断内容标 `[待确认]`（详见 `references/short-video-studio.md` 第五节，短剧侧同样适用）。

**发布包装是交付的一部分。** 短剧的后期台除了成片，交付时同时给封面（最佳帧）与分享文案；短视频的发布台要求更全（封面文案、发布文案多平台变体、话题标签、评论区引导）。只交成片不算交付完成。

## 八、单集推进示例

```bash
# 0. 建项目
python scripts/studio.py init "SD-001_剧名" --episodes 3 --title "剧名"

# 1. 剧本台：写第1集/剧本.md，出 @引用名清单

# 2. 角色与场景台：按清单出素材/，场景建场景板
python scripts/check_refs.py "SD-001_剧名"

# 3. 分镜台：写分镜 JSON，机检，出关键帧定稿
python scripts/validate_storyboard.py "SD-001_剧名/第1集/分镜/sb.json"
python scripts/lint_prompt.py --script "SD-001_剧名/第1集/剧本.md"

# 4. 出片台：逐镜出视频，记清单，核对同源
python scripts/manifest.py init "SD-001_剧名/第1集/分镜" --batch ep1 --script-version v1
python scripts/manifest.py verify "SD-001_剧名/第1集/分镜"

# 5. 后期台：拼接、配音、接缝量化、验收
python scripts/qa_batch.py "SD-001_剧名/第1集/成片"

# 随时看进度
python scripts/studio.py status "SD-001_剧名"
```

## 九、一条纪律

**工位门禁不过不进下游工位。** 这不是流程洁癖：分镜 JSON 不合格就直接出视频，返工成本是分镜阶段改十几次都赶不上的。`studio.py check` 把所有机检串成一条命令，跑一次就知道能不能往下走。
