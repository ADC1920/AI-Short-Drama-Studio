# 短剧工作室：十段弹性路由

流程骨架是「十个阶段各自有产物与门禁，可从任意一段进入，上游改动只把下游标为过期」。
旧的三路线（A 智能体分镜 / B 宫格直生 / C 人脸规避）仍是段内技法；旧的五工位仍是 05/06/08/09/10 段。
完整的段定义、四种入口模式与回退规则见 `references/stage-router.md`，本篇只讲数据契约与工位实操。

## 一、为什么改

早期三路线模型解决的是「手头材料不同，从哪进入」；v2 五工位解决的是「产物放哪、改稿往哪回流」。真实制作里还卡住第四件事：**入口不弹**。用户手上有最终剧本、只有一句概念、或只想改第 8 场，都被迫从前序开始补齐。

十段路由把这件事变成结构：**每段有最小输入与唯一输出，可以从资料能支持的那段直接进**。同时保留五工位的产物驱动与改稿回流——进度仍然只认文件。

## 二、十段与产物

| # | 阶段 | 产物 | 门禁 | 旧称谓 |
|---|---|---|---|---|
| 01 | 概念锚定 | `01_story/synopsis.md` | 三路径模板齐；一句话故事可复述 | 新增 |
| 02 | 角色圣经 | `01_story/characters.md` | 三维表齐；声音可辨测试 | 新增 |
| 03 | 世界观（可选） | `01_story/worldbuilding.md` | 规则四问；知识层级表 | 新增 |
| 04 | 分场大纲 | `01_story/第N集/treatment.md` | 逐场四问；六个审计标签 | 新增 |
| 05 | 剧本融合 | `02_script/第N集/剧本.md` | `check_script.py` 无错误 | 剧本台 |
| 06 | 资产与场景板 | `03_assets/`、`场景板/` | `check_refs.py` 无断链 | 角色与场景台 |
| 07 | 表演层（可选） | `04_performance/第N集/acting-vNN.md` | 五支柱自检 | 新增 |
| 08 | 分镜与提示词 | `05_shots/第N集/`、`06_prompts/第N集/` | `validate_storyboard.py` PASS；`lint_prompt.py` | 分镜台 |
| 09 | 出片与台账 | `05_shots/第N集/视频段/*.mp4` | `manifest.py verify` 同源；重生率 ≤10% | 出片台 |
| 10 | 后期与发布 | `05_shots/第N集/成片/*.mp4`、发布包 | `qa_batch.py`；视觉验收真看 | 后期台 |

进度只认产物：`studio.py status` 扫盘得出，人不填进度字段。

```bash
python scripts/studio.py init <项目目录> --title "剧名" --episodes 3
python scripts/studio.py status <项目目录>          # 十段进度 + 当前焦点段 + 改稿提示
python scripts/studio.py status <项目目录> --json   # 机读
python scripts/studio.py check  <项目目录>          # 串起剧本/分镜/引用/清单/场景板/提示词稿机检
python scripts/studio.py board  <项目目录>          # 出单文件 HTML 看板（默认 .studio/board.html）
```

看板是只读视图：所有状态由扫盘算出，界面上不能改，写操作一律回 CLI。这样「进度只认产物」这条纪律才不会被绕开。视觉规范留档在 `docs/design-specs/studio-board.md`。

## 三、数据契约

```
<项目>/
├── studio.json                 配置：form / title / aspect / model / episodes / layout
├── 00_project/
│   ├── brief.md                项目常量：受众、平台、时长、类型、视觉方向、预算、禁项
│   ├── project-status.md       变量：运行模式、目标阶段、权威输入、已确认文件、可能过期下游
│   ├── routing.md              本轮路由：当前阶段、唯一输出、允许读取、方法来源
│   └── history/                修订留档（旧版移入，不删除）
├── 00_inbox/                   用户上传资料登记
├── 01_story/
│   ├── synopsis.md             01 概念
│   ├── characters.md           02 角色
│   ├── worldbuilding.md        03 世界观（可选）
│   └── 第N集/treatment.md      04 分场
├── 02_script/第N集/剧本.md      05 剧本融合
├── 03_assets/                  06 资产：根级全剧共用
├── 04_performance/第N集/       07 acting-vNN.md
├── 05_shots/第N集/
│   ├── sb.json                 08 分镜 JSON
│   ├── grid01.png              08 定稿关键帧 = 该镜首帧
│   ├── _manifest.json          09 每段视频的提示词版本与场景 state
│   ├── 视频段/段01.mp4 …       09 出片产物
│   ├── 成片/第N集_成片.mp4      10 后期产物
│   └── 尾帧.md                 集间衔接用
├── 06_prompts/第N集/           08 成品提示词 cinedance-vNN.md
└── 场景板/                     场景单数据（跨集共用）
```

`studio.json` 只存手填项，进度一律扫盘。三份控制文件里**不写故事内容**——它们是控制面，创作产物在 01-06 各目录。

**旧布局兼容**：v2 项目（根下 `第X集/{剧本.md,分镜/,成片/}` + `素材/`）不迁移，`studio.py` 按 `studio.json` 的 schema/layout 与磁盘特征自动识别为 v2 布局，上游四段与表演层显示「可跳过」。

## 四、改稿回流规则

改稿的代价随段递增：概念改动最便宜，成片重出最贵。所以改一层，必须回流到它下游的所有段，禁止只改一处就交付。

| 改动发生在 | 必须回流 | 可保留 |
|---|---|---|
| 01 概念 / 02 角色 / 03 世界观 | 04 分场重审 → 05 剧本改写 → 08 分镜重写 → 09 重出 → 10 重剪 | 未受影响的集 |
| 04 分场 | 05 剧本改写该场 → 08 分镜 → 09 重出 → 10 重剪 | 角色、资产 |
| 05 剧本（台词、剧情） | 08 分镜重写受影响镜头 → 09 重出那些镜头 → 10 重剪 | 未受影响的镜头及资产 |
| 06 资产（外形、服装、场景 state） | 08 重出受影响关键帧 → 09 重出用到它的镜头 → 10 重剪 | 剧本、其它角色 |
| 07 表演 | 08 提示词重写该镜 → 09 重出 → 10 重剪 | 资产、其他镜头 |
| 08 分镜（提示词、构图、镜序） | 09 重出该镜 → 10 重剪 | 资产 |
| 09 出片（单段重拍） | 10 重剪该段 | 其余段 |
| 10 后期 | 无 | 全部上游 |

`studio.py status` 会自动比对文件时间，给出三类提示：上游创作段晚于剧本、资产晚于成片、分镜晚于视频段。看到提示就按上表回流，不要跳过回流直接交付。

## 六、另一种形态：短视频

本技能有两种形态，共用同一套十段骨架与七目录契约：

|  | 短剧形态（默认） | 短视频形态 |
|---|---|---|
| 建项目 | `studio.py init <目录>` | `studio.py init <目录> --form short --target 60` |
| 推进单位 | 每集一个目录 | 整个项目一条 |
| 脚本 | `02_script/第N集/剧本.md` | `02_script/脚本.md` |
| 末段 | 后期与发布（拼接、配音、成片） | 发布台（成片 + 发布包） |
| 上游四段 | 建议走完 | 01/04 可选，02/03 更可选 |
| 特有机检 | 引用核对、场景 state 同源 | 口播时长预算、钩子位置、发布包完整 |

短视频形态的完整工艺（时长预算反推、三档节奏、Hook 六分类、追问失效防御、发布包四件）见 `references/short-video-studio.md`。

判形态的口径：**一次交付一条、总时长 ≤60 秒、以抓停和发布为导向** → 短片形态；**多集、有角色延续、有集间衔接** → 短剧形态。两者目录兼容，短片起手后续扩成系列短剧不用搬家。

## 七、通用机制（两种形态共用）

以下四条来自同业实践，写进任何段都要遵守：

**单镜时长下限 1.5 秒。** 低于此值模型来不及完成切镜，两镜会糊成一团。现有「单序列 ≤6 镜」是上限，这条是下限，两头都要卡。

**否定约束配正向清单。** 只写「不要 X」，模型要么把 X 相关的一切掐死（画面死板），要么照旧乱加（禁令失效）。正确做法是双清单：禁止项 + 允许项，允许项每项带理由、质感参照、动态约束。例：

> 禁止：不出现霓虹光效、不出现镜头光斑
> 允许：允许暖色台灯的柔光溢出（参照钨丝灯的暖黄，范围限于灯罩周围 30cm）

这与「否定失效三改法」（换词根/主体优先句式/移除触发器）互补：三改法管「怎么把否定写对」，双清单管「否定之外还有什么可以做」。

**需求收集防四种走样。** AI 收集需求时容易：凭印象瞎问、和气接受敷衍、自我满足提前结束、编造用户没说的内容。防御办法是每次收集前对照六维清单，用户答「随便」必须追问，推断内容标 `[待确认]`（详见 `references/short-video-studio.md` 第五节，短剧侧同样适用）。

**发布包装是交付的一部分。** 短剧的 10 段除了成片，交付时同时给封面（最佳帧）与分享文案；短视频的发布台要求更全（封面文案、发布文案多平台变体、话题标签、评论区引导）。只交成片不算交付完成。

## 八、单集推进示例

```bash
# 0. 建项目（七目录 + 三份控制文件）
python scripts/studio.py init "SD-001_剧名" --episodes 3 --title "剧名"

# 1. 01 概念 / 02 角色 / 04 分场（03 可选）
#    → 01_story/synopsis.md · characters.md · 第1集/treatment.md

# 2. 05 剧本融合：写 02_script/第1集/剧本.md，出 @引用名清单
python scripts/check_script.py "SD-001_剧名/02_script/第1集/剧本.md"

# 3. 06 资产：按清单出 03_assets/，场景建场景板
python scripts/check_refs.py "SD-001_剧名"

# 4. 07 表演（可选）→ 04_performance/第1集/acting-v01.md

# 5. 08 分镜与提示词：写 05_shots/第1集/sb.json 与 06_prompts/第1集/
python scripts/validate_storyboard.py "SD-001_剧名/05_shots/第1集/sb.json"
python scripts/lint_prompt.py --text "SD-001_剧名/06_prompts/第1集/cinedance-v01.md" --line general

# 6. 09 出片：逐镜出视频，记清单，核对同源
python scripts/manifest.py init "SD-001_剧名/05_shots/第1集" --batch ep1 --script-version v1
python scripts/manifest.py verify "SD-001_剧名/05_shots/第1集"

# 7. 10 后期：拼接、配音、接缝量化、验收
python scripts/qa_batch.py "SD-001_剧名/05_shots/第1集/成片"

# 随时看进度
python scripts/studio.py status "SD-001_剧名"
```

## 九、三条纪律

**门禁不过不进下游段。** 这不是流程洁癖：分镜 JSON 不合格就直接出视频，返工成本是分镜阶段改十几次都赶不上的。`studio.py check` 把所有机检串成一条命令，跑一次就知道能不能往下走。

**一次只执行一个阶段。** 不同段的方法互相串味是这条纪律要防的事。想改别的段，等用户明确要求再切。

**未确认不改其他阶段已定内容。** 用户确认过的东西，不因为「顺便发现更好」就改掉；用户要求改上游时，留版本、切回该段、标下游受影响项，不自动重写。
